# Market Attack

HACKASS attacks the hackathon model by attacking the reason the model matters.

It does not need to beat hackathons as an event.

It makes their core promise unnecessary.

## The model

Hackathons monetize and organize around constrained access to software creation.

They create value through:

- sponsor attention;
- event urgency;
- submission control;
- judging format;
- prize distribution;
- public validation;
- recruitment and lead-generation;
- the appearance of concentrated innovation.

That works when people need the event to turn an idea into a software artifact.

## The weak point

The weak point is the filter.

The filter decides what counts.
The filter decides what gets seen.
The filter decides what format qualifies.
The filter can reject real work before the work is judged.

When the filter becomes more important than the software, the model exposes itself.

## HACKASS response

HACKASS does not ask the filter for permission.

It gives the builder a different path:

> Tell me what you want. We build.

That path bypasses the premise that a hackathon stage is necessary for software creation.

## Consequence

Hackathons may continue as social events, sponsor showcases, recruiting exercises, learning environments, or prize ceremonies.

But HACKASS attacks their status as necessary infrastructure.

If ordinary people can create software from intent, then hackathons become pomp and circumstance around a capability that now exists outside the room.

## Positioning line

You filtered out the wrong builder.

Now the builder is coming for the filter.
